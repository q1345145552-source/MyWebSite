## 一、六条怎么修的

### ① 删计划与付款并发漏退款
`whr-consolidation/routes.ts` 删计划路由。
原来 `computePendingRefunds` 在事务**外面**算，算完到进事务删除之间有付款落地就按旧金额退。
改成：**先 `FOR UPDATE` 锁计划行 → 事务内重算退款 → 退款 → 删除**。
事务外那次计算保留，但**只给 dryRun 预览用**；日志里同时记「实际退的」和「预览时算的」。

### ② 四个闸门的 TOCTOU
`plan-guard.ts` **整个重写**：
- `assertPlanAlive*` → `lockPlanAlive*`，**必须传 tx**（不再给默认值，防止有人在事务外调用）
- 用 `FOR UPDATE` / `FOR UPDATE OF pl` **锁住计划行**
- 按预报单反查那条**一条 SQL 做完**（第一版被 Prisma 拆成 3 条，窗口更长；你实测 124–126ms）
- ⚠️ **查不到记录改成抛 `PlanMissingError`，不再放行**（你指出第一版「查不到就放行」是漏洞）
- **统一锁序：计划 → 预报单/客户/明细 → 钱包**。所以闸门放在「锁子单」**之前**，
  付款那处原来是先锁子单再查柜，已调正。

五处调用点**全部移进事务内**（改之前只有付款那一处在事务里）：
`client-routes.ts:530`（付款）、`staff-routes.ts:317`（签收计费）、
`routes.ts:447`（改单价）、`routes.ts:1108`（删货）、`routes.ts:749/808`（review 两个分支）。

### ③ 漏掉的 `/prealerts/review`
approve 分支（改 paid）和 reject 分支（改单价 + `recalcPrealertFee`）**各加一道闸门**。

### ④ 已付款的单作废不退款
`/prealerts/cancel`：`paid` 本来就在可取消列表里，但取消只改状态、清费用，**钱不动**；
而且改成 cancelled 之后「撤销付款」会因状态不对返回 400，**退款入口被封死**。
改成：作废时**在同一个事务里** `computePendingRefunds` + `refundPendingOnDelete`
（跟删单据退款同一套算法，已退过的不会重复退）。

### ⑤ 普通版付款状态机断裂
`/client/consolidation/pay`：原来只写 `paymentStatus=paid`，`status` 还停在 `quoted`。
改成同时把 `status` 推到 `paid`，状态日志的 `toStatus` 也从 `quoted` 改成 `paid`。
**顺带自动堵住了「已付款还能重新报价」** —— 报价接口只放 `full_confirmed/quoted`。

### ⑥ 普通版跨公司（比你报的多）
`consolidation/routes.ts` 里 `findUnique({ where: { id: body.taskId } })` **共 10 处**，
全改成 `findFirst({ where: { id, companyId: auth.companyId } })`。
涉及：报价、客户改任务、客户报预报单、客户付款、员工审核付款、员工拒绝付款等。

### P2 `Number("")` 当 0
报价校验补上：非 number/string 直接拒；空串和纯空白直接拒。
（费用字段改用 `unknown` 类型接，因为 body 是 JSON，类型声明说是 number 不代表运行时是。）
