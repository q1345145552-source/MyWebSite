### ① AI 数字对上了、名称被换掉（`fbe1866`）

**本地复刻成功**，输出跟老板看到的一模一样：一共 3 单（在途 2、已完成 1），
客户看到「已完成：3 单 / 在途中：2 单 / 总单量：1 单」。

根因：占位符方案的五道检查（各出现一次 / 编号合法 / 顺序一致 / 外面没数字 /
外面没中文数量词）**全都只盯占位符本身**，没有一道管「这个数挂在哪个名称底下」。
模型一个占位符都不用动，只把「总单量：」「已完成：」两个**文字标签**调换位置，五道全过。

改法：`maskNumbers` 改成**一趟扫描、按文档顺序编号**，
把「名称：数字+单位」这种行**连名称一起**遮成一个占位符。
模型看到的变成光秃秃的 `⟦N2⟧⟦N3⟧⟦N4⟧`。

**请你重点挑：**
1. 我用了 `(?<=^|\n)[^\n：:]{1,16}[：:]\s*数字单位` 这个前瞻。
   **有没有哪一行本不该被整行吞掉却被吞了？** 比如「最近更新时间：2026-08-28 09:47」
   （我判断它不匹配，因为日期后面没有单位），「当前状态：delivered」（没数字）。
   请把 `formatSummaryAnswer` / `formatProgressAnswer` / `formatNoData*` 的**所有**输出形态
   过一遍，看有没有我漏掉的。
2. **必须一趟扫完** —— 分两趟（先遮带名称的、再遮裸数字）会让编号和出现顺序对不上，
   「顺序一致」那道会把每一次润色都误判成违规，润色就永远不生效了。
   请确认我这个单一正则的分支优先级没写反。
3. **代价**：统计明细那几行模型现在改不动了。我认为那本来就是数据表、不是要润色的人话。
   **这是我的判断，请你反驳。**

### ② 批量下单产品数量漏乘箱数（`8e464e2`）

老板实测：三行明细各填 2/3/4 箱、每箱 2/3/4 个，正确 2×2+3×3+4×4 = **29**，系统报 **9**。

根因：`batchOrderImport.ts` 的汇总里**同一个函数三个算法不一致** ——
重量 `× packageCount` ✅、体积 `× packageCount` ✅、唯独数量 `sum + productQuantity` ❌。

⚠️ 而且 `orders/routes.ts:843` 那条注释白纸黑字写着
「批量导入那条路不受影响，解析器本来就会把订单级的合计算好」——
**那句话是错的**，已一并更正。

顺带把表头改了：模板这一列原来叫「产品数量」，跟旁边的「**单箱**重量kg」口径不一致，
员工很容易当成「这一行一共几个」填。改成「单箱数量（每箱几个）」，
**解析器新旧两个表头都认**（`findValue` 是包含匹配）。

**请你重点挑：**
1. **口径对不对。** 老板拍板 29 是正确答案（= 单箱数量）。
   请你把**所有**算「产品总数量」的地方找一遍，确认没有第三处口径不一致的。
2. **表头改名的连带影响。** 如果历史上有员工按「总数」填过这一列，
   改完之后他们的数字会被乘上箱数 → **报大**，这是危险方向。
   请评估这个风险，以及「两个表头都认」会不会在一张表同时有两列时认错。
3. **部分填写的情况**：某几行填了单箱数量、某几行没填时，没填的按 0 计入，
   总数会偏小。重量和尺寸都有「要么全填要么全空」的校验，数量这一列**没有**。
   我没动它（怕拦住现在能用的导入）。**请你判断该不该补这道校验。**

### ③ 多尺寸整柜导出长宽高空白（`115aaa8`）

老板实测：单尺寸能导出，「60/50」这种多尺寸三格全空白。

**请你重点挑：**
1. **文本格写进那三列会不会把 xlsx 写坏。** 我的判断是安全的：
   `clearRange` 本来就是用 `setTextCell` 走这三格的，格子肯定存在。请你验证。
2. **绝对不能出现的两种错修**（我避开了，请确认我真的避开了）：
   ❌ 让字符串直接进 `setNumberCell` → `Number.isFinite` 挡下后写 `0`，纸上印出「长 0 宽 0 高 0」；
   ❌ 用 `parseFloat("60/50")` 兜底 → 静默取到 60，把两种规格印成一种。
3. **「只有长不同」的半行情况**：后端 `pick` 是**每个维度各自去重**的，
   所以可能出现 length 是字符串、width/height 是数字。请确认这种混合情况我处理对了。
4. **方数不能变。** CLAUDE.md 第 33 条的教训。我的第 3 项测试盯着这个，请你也核一遍
