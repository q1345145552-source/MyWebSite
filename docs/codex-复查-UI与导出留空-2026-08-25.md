## 一、改了什么（5 处，都要复查）

### 1.1 `viewModel.ts` — 没填的元数据不再写「未填写」

`summarizeLastmileMeta()` 在一个值都没有时，原来返回 `{ display: "未填写", full: "未填写" }`，
现在返回 `{ display: "", full: "" }`。

**为什么**：司机 / 车牌 / 电话 / 派送日期 **本来就都是选填的**，没填是常态。
浏览器实测：6 张 WD 卡片里 **16 个格子**写着「未填写」，整屏灰字全是噪音。

**要复查**：这个函数还有没有别的调用方依赖「未填写」这个字符串（例如搜索、导出、判空）。
实测只有 `LastmileDispatchWorkspace.tsx` 的 driver/plate/phone/date 四处在用，请再确认一遍。

### 1.2 `LastmileDispatchWorkspace.tsx` — 去掉签收进度条

删掉了 `<div className="lastmile-progress-track">`，同时删掉了不再使用的 `progress` 变量。
**保留** `签收进度 3/5` 那行文字。

**为什么**：条子旁边已经写着 `3/5`，不提供新信息；而且它是 `border-radius: 999px` 的全圆角胶囊，
用户明确说过界面不要这类装饰。

**要复查**：`.lastmile-progress-track` 和 `.lastmile-wd-progress` 的 CSS 现在有没有变成死规则；
`.lastmile-wd-progress > div:first-child` 那条 `margin-bottom: 5px` 还需不需要。

### 1.3 `LastmileDispatchWorkspace.tsx` — 四格全空时整行不渲染

`<div className="lastmile-trip-meta">` 外面包了一层判断：
`driver.display || plate.display || phone.display || date.display` 才渲染。

**为什么**：四个都没填时，那一整行只是四个空格子加四个标签，纯占地方。
**只要有一个填了，四格照常并排显示，列宽和顺序完全不变。**

**要复查**：`.lastmile-trip-meta` 有 `border-bottom`，整行不渲染之后，
卡片头部和客户列表之间的分隔线会不会缺一条、间距会不会塌。**这一条请在浏览器里看，别只读 CSS。**

### 1.4 `exportDispatchWorkbooks.ts` — 没填的体积/重量留空，不印 0

三处改动：
- `TemplateLine.volumeM3 / weightKg` 类型从 `number` 改成 `number | null`
- 新增 `setOptionalNumberCell()`：值为 null / undefined / 非有限数时调 `clearCellXml()` 留空
- 算 volume / weight 时先判空：**`shipment.volumeM3` 可能是 null，而 JS 里 `null * share === 0`**，
  不判空就会把「没填」算成「0 方」
- 新增 `optionalLineTotal()`：整列一个值都没有时返回 null（用于泰语页 F28/G28 两个数值合计格）

**为什么**：客户派送签收单是**给客户签字的纸质单据**。生产实测有运单体积重量为 null，
导出后印成「0 m³ / 0 kg」，等于白纸黑字告诉客户这箱货没有重量。

**要复查**：
- `setNumberCell` 的其它调用方（件数、序号、长宽高、L3/L5）**有没有被误改**，它们应该保持原样
- `lineTotal()` 用 `Number(line[key] || 0)`，null 会被当 0 —— 合计时这是对的（只加有值的），请确认

### 1.5 `admin/page.tsx` — 从没设过价的柜子，按钮不再写「已保存」

按钮文字判断从 `dirty ? "保存" : "已保存"` 改成
`dirty ? "保存" : (item.price === null ? "保存" : "已保存")`。

**为什么**：浏览器实测 18 个柜子全没设过价，18 个按钮却都写着「已保存」，看着像已经填过了。

**要复查**：`item.price` 为 `0` 时（真的设成 0 元）会不会被当成「没设过」。
`0 === null` 是 false，所以应该没问题，但请确认后端返回的确实是 `null` 而不是 `0` 或 `"0"`。

## 三、已知且**故意不改**的（不要"顺手修好"）

**中文页合计格 `E16/F16/G16` 在全空时仍显示 0。**

那三格是 Excel 公式 `SUM(E6:E15)`，对空格子求和在 Excel 里天然就是 0。
把公式删掉换成空白确实能不显示 0，**但员工以后在 Excel 里手填数字就不会自动合计了**，得不偿失。
明细行已经是空白的，合计显示 0 在上下文里不会误导。

**这是权衡后的决定，请不要改。** 如果你认为有更好的办法（例如公式改成
`IF(COUNT(F6:F15)=0,"",SUM(F6:F15))`），**先说方案，不要直接改**。
