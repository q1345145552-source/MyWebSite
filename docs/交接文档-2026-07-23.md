## 1. 项目概述

中泰跨境物流管理系统，三端合一（管理员/员工/客户端），覆盖**预报单 → 装柜 → 清关 → 卸柜 → 到仓 → 尾端派送 → 签收**的完整物流链路。

## 9. 关键架构决策 & 陷阱

### 9.1 三端 API 独立编写

**管理员端、员工端、客户端的 API 是独立编写的，没有共用数据层。** 改一个端的 API，必须手动检查另外两端。

```bash
# 改任何 API 前先 grep 全局影响
grep -rn "接口路径" apps/ --include="*.ts" --include="*.tsx"
```

### 9.2 父子运单逻辑

- **运单列表**：只看父运单（`parentTrackingNo: null`）
- **装柜**：看子运单
- **尾端派送**：看子运单
- **编辑查重**：排除自己的 ID

### 9.3 图片系统

- 图片存储：数据库 `order_product_images` 表（`content_base64` 字段）+ 磁盘文件
- 磁盘路径：容器内 `/images/` → 宿主机 `/root/MyWebSite/data/images/`
- API 静态服务：`GET /images/filename` → 直接从磁盘读取
- 环境变量：`IMAGES_DIR=/images`（**必须在 docker-compose.yml 中设置**）
- 前端 URL：浏览器端 `apiBaseUrl()` 返回空字符串，图片走相对路径 → Next.js rewrite 代理到 API
- 图片恢复：如果磁盘文件丢失，可从 DB 的 `content_base64` 字段恢复

### 9.4 Docker Healthcheck IPv6 陷阱

Alpine 容器中 `localhost` 优先解析到 IPv6 `::1`，但 Node.js 只监听 IPv4。Healthcheck 必须用 `127.0.0.1`：
```yaml
test: ["CMD-SHELL", "wget -qO- http://127.0.0.1:3001 -T 3 || exit 1"]
```

## 10. 全部教训（19 条）

| # | 错误 | 教训 |
|---|---|---|
| 1 | 删了常量但下游还在引用 | 删之前 grep 全局 |
| 2 | Prisma select 写了不存在的字段 | 查 schema 确认字段存在 |
| 3 | 所有图片 base64 塞进响应 | 大数据量字段不要随列表返回 |
| 4 | 加了函数调用忘了 import | 写完检查 import 区 |
| 5 | 改 rewrite 规则导致请求匹配不上 | 改配置全链路测试 |
| 6 | 事务回调没 return 导致变量引用崩溃 | 事务回调最后 return 数据 |
| 7 | 改构建流程没本地先跑 | 构建改动先验证 |
| 8 | 给 model 加字段后只改了部分端的 API | **三端 API + 前端逐个检查**，grep 确认所有引用点 |
| 9 | 组件提取后遗留未使用的 import 和死代码 | 改动完成后收尾清理：冗余 import、死代码、重复逻辑 |
| 10 | 改表头列顺序只改了 `<th>` 没同步改 `<td>` | `<th>` 和 `<td>` 必须一起改，逐列对照 |
| 11 | 员工端不过滤 `parentTrackingNo: null` | **三端列表查询条件必须对齐**：`parentTrackingNo: null` + `take: 500` |
| 12 | 改 API 过滤条件没查所有调用方 | **改 API 前 grep 全局调用方**，逐个评估影响 |
| 13 | 派送单号用 `count()` 生成 | **用 `max` 不用 `count`**，避免删除后重复 |
| 14 | 分柜后各模块处理父子运单逻辑不一致 | **逐个模块梳理「该看父还是该看子」** |
| 15 | API 加默认 pageSize 前端没传参 | **改 API 默认值时 grep 全局调用方** |
| 16 | 前端参数名和 API 不匹配 | **前后端参数名必须一致**，不匹配不会编译报错 |
| 17 | 查重依赖前置相等判断 | **直接查重 + 排除自身 ID**，不依赖前置判断 |
| 18 | 唛头列 width 太小被截断 | **ID/编号类字段 ≥100px + `whiteSpace: "nowrap"`** |
| 19 | 部署时没同步 DB + 环境变量丢失 + 图片磁盘文件消失 | **deploy.sh 加固：变更展示、DB 同步重试、环境检查、图片校验** |

## 11. 常见故障及修复

### API 返回 500（`column does not exist`）

**原因：** Prisma schema 有人加了新字段，数据库没同步。

```bash
cd /root/MyWebSite
docker compose exec -T api npx prisma db push --schema=apps/api/prisma/schema.prisma --accept-data-loss
docker compose restart api
```

### 图片全部打不开

**原因 A：** 容器重建后 `IMAGES_DIR` 环境变量丢失。

```bash
# 检查 docker-compose.yml 中 api service 是否有 IMAGES_DIR: /images
grep IMAGES_DIR docker-compose.yml
# 如果没有，加上后重建容器
```

**原因 B：** 磁盘图片文件丢失但数据库有记录。

```bash
# 从数据库恢复图片文件到磁盘
docker compose exec -T api node -e "
const { PrismaClient } = require('@prisma/client');
const fs = require('fs'); const path = require('path');
const prisma = new PrismaClient();
(async () => {
  const imgs = await prisma.orderProductImage.findMany({
    where: { filePath: { not: '' }, contentBase64: { not: '' } },
    select: { id: true, filePath: true, contentBase64: true }
  });
  let r = 0;
  for (const img of imgs) {
    const f = path.join('/images', path.basename(img.filePath));
    if (!fs.existsSync(f)) { fs.writeFileSync(f, Buffer.from(img.contentBase64, 'base64')); r++; }
  }
  console.log('恢复: ' + r);
  await prisma.\$disconnect();
})();
"
```

### 容器 unhealthy 但服务正常

**原因：** Healthcheck 使用 `localhost`（IPv6），改成 `127.0.0.1`（IPv4）。

已在 docker-compose.yml 中修复。

### 磁盘空间不足

**原因：** Docker Build Cache 堆积。

```bash
docker builder prune -af   # 清理 30-40GB，不影响数据
```
