## 一、开工前必须先做的两件事（不做会浪费老板时间）

### ① 拿到登录状态后，第一件事是备份

这个项目有个坑：**登录页一打开就会清掉 localStorage 里的登录信息**
（`apps/web/src/app/login/page.tsx` 挂载时调 `clearAuthSession()`）。
一旦被弹回登录页，会话就没了，只能再麻烦老板登一次。

所以拿到登录状态后**立刻**在控制台执行：

```js
localStorage.setItem('__bak_auth', localStorage.getItem('auth_session_v1'))
```

被弹走了就用这个恢复：

```js
localStorage.setItem('auth_session_v1', localStorage.getItem('__bak_auth')); location.href='/staff'
```

### ② 不要改前端文件

改 `RoleShell.tsx` 之类的组件会触发热更新，**热更新会把浏览器里的登录状态弄掉**
（本地开发才有的现象，线上不会）。这次是验收，本来也不该改代码。

### 🟠 5. 手机端不能被连累（我只有静态证明，没实测这一版）

2. 把浏览器窗口拉窄到 **900px 以下**（或用开发者工具的手机模式）

### 🟡 6. 那两个按钮有没有被全局规则污染

`globals.css:1216` 有条兜底规则：

```css
button:not([style*="background: transparent"])... { background: var(--brand); color: var(--white); }
```

它把页面上**每一个** `<button>` 都刷成实心品牌蓝，而且特异性比类名高。
我第一版就中招了 —— 两个小按钮长成了两颗实心蓝主按钮
（A3 规格是「一个页面只留一个实心主按钮」）。
现在是按旁边 `.mobile-hamburger` 的同款写法用 `background: transparent !important` 躲开的。

请确认：两个按钮是**描边样式**不是实心蓝；hover 有反馈；深色底上看得清。

## 四、我第一版犯的三个错（说出来方便你判断我这个人的结论可不可信）

1. **验证用错了外观。** 20 个页面全部是 `variant="a3"`（深藏青、侧边栏 172px），
   我却拿默认外观（浅色、280px）做的预览 —— 等于验了一个系统里不存在的样子。
2. **给标题包了层 flex**，把 a3 品牌标题的 20px 下边距挤成 12px，整排菜单上移 3px。
3. **按钮进了文档流**：顶栏是 `flex + space-between`，多一个子元素就把标题挤到正中间
   （x 从 208 跳到 654），顶栏还从 44px 长到 53px。

三条都是**我自己后来重测才发现的**，第一版提交时我以为没问题。
所以**请不要相信我说「已经验过了」** —— 该量的自己量一遍。
