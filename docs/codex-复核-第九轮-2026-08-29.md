## 一、这一轮改了什么

### 1.1 批量锁运单：不再靠推理，改成真去查
新增 `apps/api/src/modules/shipments/lock-shipments.ts`：
- `lockShipmentsChildrenFirst()` —— **锁之前真查一遍父子关系**，
  分两层（子单 → 父单）、层内按 **id** 排序

### 1.2 🆕 父单锁的排序键统一成 id（**这条你没报，是我自己派的排查挖出来的**）
我抽出上面那个函数时父单层按 **id** 排，而系统里三处「第二轮同步父单」
是按**运单号**排的（`syncParentStatusFromChildren` 内部锁 `WHERE tracking_no = ...`）。
**同一批父单两把钥匙**，照样能锁反。只读查测试库：
**id 顺序和运单号顺序相反的父单对有 41 对**。
现在新增 `lockParentsByTrackingNo`（换算成 id 再排）和 `lockAndSyncParents`
（**把循环也收进去**，不给调用方写错的机会）。

### 1.3 管理员端最后两处「猜成 1」
`admin/page.tsx:2529` 输入框 onChange 就是 `Math.max(1, ...)`（清空的那一刻就变 1）、
`:2642` 旧批量导入 `?? 1`。

### 1.4 整数校验：新增 `core/int-guard.ts`
覆盖「没有产品行时的订单级箱数」「**合计溢出**」「仓库版集货小数/上限/乘积溢出」
「装柜件数小数」。

### 1.5 响应扫描：不再追正则，改成结构上堵死

### 1.6 登录时间侧信道：**只改了注释，没改代码**
